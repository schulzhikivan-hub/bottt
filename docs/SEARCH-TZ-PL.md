# Поиск для доски объявлений и знакомств (Польша): системный анализ

**Допущения, принятые в документе** (всё, что не подтверждено, вынесено в раздел 12):
- В знакомствах **нет** матчей, лайков, взаимных симпатий и чата по симпатиям. Услуга «супер-лайк» из списка платных не проектируется.
- Анкета знакомств находится через поиск и фильтры, как объявление.
- «Приватные фото (только VIP)» понимается так: владелец помечает часть фото приватными, видят их **только зрители с активной услугой VIP** (уточнение в разделе 12).
- Источник правды один: база сайта. Админка и бот вызывают **один и тот же** слой поиска.
- Нормативные значения для Польши (документы, визы) требуют проверки юристом на дату запуска.

## 1. Модель поискового индекса

### 1.1. Что индексируется

Один логический индекс, одна запись на объект, поле `doc_type`.

| doc_type | Что это | Связи |
|---|---|---|
| `listing` | объявление (работа, жильё, вещи, услуги) | автор, категория, город, фото, поля из конструктора |
| `profile` | анкета знакомств | владелец, город, фото публичные и приватные |
| `resume` | резюме | владелец, город |
| `review` | отзыв | объект отзыва (объявление или человек), автор отзыва |
| `employer_request` | заявка работодателя | компания, вакансия, город |

### 1.2. Общие поля записи

| Группа | Поля | Хранится / вычисляется |
|---|---|---|
| Идентификация | `doc_type`, `id`, `author_id`, `category_id`, `source` (web/bot/api) | хранится |
| Статус | `status` (draft, pending, published, rejected, needs_fix, hidden, closed, expired, deleted, archived) | хранится |
| Срок жизни | `published_at`, `expires_at`, `bumped_at`, `renewed_count` | хранится |
| Видимость | `visible` (bool) | **вычисляется при записи** и **перепроверяется при запросе** по времени |
| Локация | `city_id` (код SIMC), `voivodeship_id` (16), `district_id` (powiat/dzielnica), `postcode` (NN-NNN), `lat`, `lng` (если есть) | хранится |
| Текст | `title`, `body`, `tags`, `search_text` (сырой, нижний регистр), `search_fold` (без диакритики), `search_lemma` (леммы), `lang` (pl/ru/uk/en) | вычисляется при записи |
| Цена | `price_pln` (целое, в злотых), `price_type` (amount / negotiable / free), `price_period` (month / hour / once), `price_gross` (brutto/netto для работы) | хранится |
| Поля категории | плоский набор `f_<ключ>` из конструктора, у каждого признак filterable / searchable / show_in_card | хранится |
| Платное | `vip_until`, `pinned_until`, `bump_at`, `contacts_unlocked`, `invisible` | хранится (даты), активность считается на запросе: `vip_until > now` |
| Доверие | `author_trust` (0–100), `author_verified` (bool) | вычисляется раз в час и при событиях |
| Модерация | `reports_open`, `reports_valid_30d`, `mod_flags` (набор: duplicate_text, duplicate_photo, same_contact, stopword) | хранится, обновляется событиями |
| Медиа | `photo_count`, `has_photo`, `private_photo_count` (только число, без ссылок) | вычисляется |

Для `profile` дополнительно: `gender`, `seeking[]`, `age` (из даты рождения на запросе, в индексе `birth_date`), `goal`, `doc_status`, `height`, `children`, `smoking`, `languages[]`, `selfie_verified`.
Для `resume`: `position`, `experience_years`, `salary_from`, `skills[]`, `work_doc`.
Для `review`: `target_type`, `target_id`, `rating`, `reviewer_id`, `tags[]`.
Для `employer_request`: `company`, `vacancy`, `salary_from`, `docs_required[]`, `verified`.

### 1.3. Правило видимости (единое, считается одной функцией для всех клиентов)

`visible = status = published AND now < expires_at AND author не заблокирован AND не скрыт жалобами AND прошла модерацию` и дополнительно:
- `profile`: `age ≥ 18` **жёстко**, `invisible = false`, есть одобренное публичное фото, анкета не на проверке.
- `resume`: владелец включил показ работодателям.
- `review`: статус «опубликован», объект отзыва видим.
- `employer_request`: только после проверки (для публичных списков), иначе виден только сотрудникам.

Для сотрудников (`scope=staff`) этот фильтр отключается, статусы становятся фильтром.

### 1.4. Как обновляется индекс

| Событие | Действие | Срок |
|---|---|---|
| Создание, правка автором | upsert, статус `pending` не виден публике | ≤ 5 с |
| Решение модератора (одобрить / отклонить / скрыть / отменить решение) | пересчёт `visible`, upsert или удаление | ≤ 5 с |
| Оплата или окончание услуги (VIP, закрепление, «невидимка», поднятие) | обновление дат | ≤ 5 с |
| Блок пользователя, снятие блока | пересчёт всех записей автора пачкой | ≤ 1 мин |
| Жалоба принята или отклонена | пересчёт `reports_*`, при ≥ 3 разных жалующихся скрытие | ≤ 5 с |
| Истечение срока | **при запросе** условие `now < expires_at` работает всегда; плюс фоновая чистка каждые 5 минут | сразу |
| Смена настроек поиска (веса, синонимы, поля) | полная переиндексация в новый индекс (раздел 10) | по запросу |

Механизм: запись события в **outbox** в той же транзакции, что и изменение, затем индексатор применяет и повторяет при ошибке. Ночью сверка: объекты в базе без записи в индексе и наоборот.

## 3. Сортировки

### 3.1. Список

| Тип | Доступные | По умолчанию |
|---|---|---|
| Объявления | Najnowsze, Najtańsze, Najdroższe, Najbliżej (если есть координаты), Najtrafniejsze (только при текстовом запросе) | при запросе: Najtrafniejsze; без запроса: Najnowsze |
| Анкеты | Najnowsze, Najtrafniejsze, Młodsze / Starsze (по возрасту) | Najnowsze |
| Резюме | Najnowsze, Najtrafniejsze, Doświadczenie (по опыту), Oczekiwania (по зарплате) | Najnowsze |
| Отзывы | Najnowsze, Najwyższa ocena, Najniższa ocena | Najnowsze |
| Заявки (админ) | Давность ожидания, Новые | Давность ожидания |

### 3.2. Как платные влияют на сортировку

Платные услуги **не меняют** ответ при сортировках «Najtańsze / Najdroższe / Młodsze / Starsze», кроме закрепления.

| Услуга | Что делает | Ограничение |
|---|---|---|
| Закрепление (pinned) | до 2 позиций над выдачей на **первой странице** раздела, подпись «Przypięte» | максимум **2** закреплённых в выдаче; не показываются, если не подходят под фильтры |
| VIP | прибавка к рангу (раздел 4), метка «VIP», показывается вперёд при сортировке «Najtrafniejsze» и «Najnowsze» | правило «окно 5 / максимум 2 платных» |
| Поднятие (bump) | `bumped_at` заменяет `published_at` для сортировки «Najnowsze» и свежести, один раз в 24 ч, эффект затухает за 24 ч | не более 1 раза в сутки на объект |

**Правило «платным не всё сверху»:**
- В любом окне из **5 подряд идущих** результатов не более **2** платных (VIP + поднятые).
- Закреплённые (до 2) стоят отдельной шапкой и не считаются в окне.
- Не более **2** результатов одного автора в первых 10; остальные «схлопываются» в «Ещё от этого автора».
- Платные в сумме не больше **30 %** первой страницы.
- Если платных мало, свободные места занимают обычные: платное **не** растягивается.

### 3.3. Что нельзя сортировать и почему

- Отзывы и заявки «по близости»: нет смысла.
- «По рейтингу автора» в публичной выдаче: легко накручивается, используется только как вес ранга.
- «По числу просмотров»: поощряет накрутку и вредит новым объектам.
- «По онлайну»: данных нет (условие задачи).
- «Najbliżej» отключается, если у объекта нет координат (иначе несправедливо ранжируются объекты без адреса); вместо неё «по городу пользователя».

## 4. Ранжирование

### 4.1. Формула (значения по умолчанию, настраиваются в админке)

`score = 40·Текст + 25·Свежесть + 15·Локация + 10·Доверие + 10·Платность − Штрафы` (0–100, штрафы до −60).

| Слагаемое | Как считается |
|---|---|
| **Текст** | релевантность по тексту (BM25 или эквивалент), нормирована 0–1; совпадение в заголовке ×2, в тегах ×1,5, в теле ×1; точное совпадение с диакритикой +10 % к текстовой части |
| **Свежесть** | `0,5^(возраст / период полураспада)`; период: объявления 7 дней, работа 10 дней, вещи 5 дней, жильё 14 дней, резюме 14 дней, анкеты 30 дней; возраст считается от `max(published_at, bumped_at)`; в последние 20 % срока жизни объект получает дополнительный множитель 0,9 (амортизация) |
| **Локация** | тот же город = 1,0; то же воеводство = 0,5; остальная страна = 0 (раздел 4.3) |
| **Доверие** | `author_trust / 100`: 0,2 за подтверждённый аккаунт, 0,2 за проверенного автора, до 0,3 за историю без нарушений (12 мес), до 0,2 за положительные отзывы, 0,1 за полный профиль |
| **Платность** | VIP = 1,0, закрепление не участвует (показывается шапкой), поднятие = 0,6 в первые сутки с затуханием, обычное = 0 |
| **Штрафы** | см. ниже |

### 4.2. Штрафы и учёт особых признаков

| Признак | Влияние |
|---|---|
| Открытая обоснованная жалоба (подтверждённая) | −10 за каждую, не больше −30 |
| Открытая необработанная жалоба | −5 за каждую (до −15) |
| ≥ 3 разных жалующихся | автоматическое скрытие до решения (не штраф, а `visible=false`) |
| Флаг `duplicate_text` / `duplicate_photo` | −20 |
| Флаг `same_contact` (один контакт у ≥ 3 аккаунтов) | −15 |
| Флаг `stopword` (предупреждение) | −10 |
| «Проверенный автор» | входит в доверие (+0,2) |
| Источник (`web` / `bot` / `api`) | **в ранг не входит**; используется для статистики, лимитов и фильтра в админке; исключение: `api` без модерации не публикуется |
| Жалобы признаны необоснованными | счётчик обнуляется, штраф снимается |

### 4.3. Локация

1. Сначала объекты из выбранного **города** (вес 1,0).
2. Потом то же **воеводство** (0,5).
3. Потом вся **страна** (0).

В выдаче разделители: «W Krakowie», затем «W województwie małopolskim», затем «W całej Polsce». Блок следующего уровня показывается, если в городе **меньше 5 результатов** или пользователь дошёл до конца списка города. Если город пуст полностью, сверху плашка «W Krakowie nic nie znaleźliśmy. Pokazujemy z województwa» и кнопка «Szukaj w całej Polsce». Для вакансий с пометкой «удалённо» или «готов к переезду» локация не ограничивает.

### 4.4. Мёртвые объекты

- Условие `visible AND now < expires_at` стоит **в каждом запросе**, а не только в индексе.
- Фоновая чистка каждые 5 минут удаляет из индекса истёкшие, закрытые, удалённые и архивные.
- Кэш выдачи не дольше 60 секунд.
- Прямая ссылка на истёкший объект: страница «Ogłoszenie nieaktualne» с похожими, а не 404, в индекс страница не попадает (`noindex`).
- Продлённый объект возвращается в индекс сразу после продления.

## 5. Локализация под Польшу

### 5.1. Морфология

Польский сильно флективный: поиск должен сводить формы к лемме.

| Запрос | Должен находить |
|---|---|
| `praca` | praca, pracy, pracę, pracą, pracą, prac (родительный мн.) |
| `pracy` | то же |
| `mieszkanie` | mieszkanie, mieszkania, mieszkaniu, mieszkaniem, mieszkań |
| `spawacz` | spawacz, spawacza, spawaczowi, spawaczy, spawaczem |
| `kierowca kat. C` | kierowca, kierowcy, kierowcę |
| `sprzątanie` | sprzątanie, sprzątania, sprzątaniem |

**Решение:** лемматизация по словарю (Hunspell `pl_PL`, Morfologik или Stempel). Если слова нет в словаре, запасной вариант: префиксный стем из первых 5–6 букв для слов от 6 букв. Леммы хранятся в `search_lemma`, запрос лемматизируется так же.
**Альтернатива:** без лемматизации только префиксный поиск (проще, но «praca» не найдёт «pracy» без стема и даёт лишнее).

### 5.2. Диакритика

Польские буквы: ą ć ę ł ń ó ś ź ż.

- В индексе два представления: исходное `search_text` и без диакритики `search_fold` (ą→a, ć→c, ę→e, ł→l, ń→n, ó→o, ś→s, ź→z, ż→z).
- Запрос **без диакритики** (`lodz`, `zolty`, `krakow`) ищется по `search_fold` и находит `Łódź`, `żółty`, `Kraków`.
- Запрос **с диакритикой** (`Łódź`) ищет по тексту точно и по fold, при точном совпадении диакритики +10 % к текстовой части ранга.
- Особый случай: `ł` не раскладывается стандартным Unicode-разложением, поэтому нужна **явная таблица замен**.
- Города в справочнике хранятся в двух формах (с диакритикой и без) плюс алиас кириллицей.

### 5.3. Опечатки

| Длина слова | Допустимое расстояние (Дамерау-Левенштейн) |
|---|---|
| ≤ 4 | 0 (точное совпадение, иначе слишком много шума) |
| 5–8 | 1 |
| ≥ 9 | 2 |

- Поправка включается, когда по исходному запросу **меньше 3 результатов** или найденное слово не встречается в словаре индекса.
- Показывать: «Wyniki dla: **spawacz**. Szukaj dokładnie: *spawaz*» (если исправление применено) или «Czy chodziło o: **spawacz**?» (если результатов по исходному нет).
- Не исправлять числа, коды, названия компаний в кавычках и слова в кавычках.
- Источник подсказок: словарь слов индекса (с частотой), чтобы не предлагать несуществующее.

### 5.4. Латиница и кириллица

Контент бывает на польском, русском, украинском и английском. Нужна двусторонняя связность по **ключевым словам**, а не машинный перевод.

- **Транслитерация** польский ↔ русский для имён, городов и названий: Warszawa ↔ Варшава, Kraków ↔ Краков, Gdańsk ↔ Гданьск, Wrocław ↔ Вроцлав, Poznań ↔ Познань, Łódź ↔ Лодзь, Katowice ↔ Катовице, Lublin ↔ Люблин, Szczecin ↔ Щецин.
- **Словарь соответствий** ключевых слов (около 300 терминов, редактируется в админке): квартира = mieszkanie, работа = praca, комната = pokój, продам = sprzedam, сдам = wynajmę, водитель = kierowca, сварщик = spawacz, уборка = sprzątanie, склад = magazyn, без опыта = bez doświadczenia, без визы = bez wizy.
- Каждый объект получает `lang`; запрос ищется **по всем языкам**, но объекты на языке интерфейса получают +5 % к тексту.
- Запрос, набранный кириллицей, раскладывается в польские эквиваленты и наоборот, результаты не помечаются «автоперевод», только бейдж языка объявления (PL / RU / UA).
- Не делать автоматический перевод текста объявления в индексе (качество и стоимость).

### 5.5. Синонимы и стоп-слова

**Стоп-слова польского (убираются из текстового запроса):** i, w, we, na, z, ze, do, od, dla, po, o, u, za, przy, oraz, lub, czy, że, to, a, jest, są, się, mój, moje.
**Не стоп-слова (важны для смысла):** bez (bez doświadczenia, bez prowizji), nie (nie palę), do и od внутри конструкций «od 3000 do 5000» (разбираются как диапазон цены, а не как слова).

**Примеры синонимов (двусторонние, если не указано иное):**
- praca = robota = zatrudnienie = etat
- mieszkanie = lokal (lokal → mieszkanie, односторонний: lokal может быть и коммерческим)
- kawalerka → mieszkanie (односторонний; kawalerka ≠ любое mieszkanie)
- pokój = pokoik
- sprzedam = sprzedaż = na sprzedaż
- wynajmę = do wynajęcia = wynajem
- kierowca = szofer
- opiekunka = opieka nad osobą starszą = opiekun
- sprzątaczka = sprzątanie = pomoc domowa
- magazynier = pracownik magazynu
- bez doświadczenia = dla początkujących = zero doświadczenia
- umowa zlecenie = zlecenie; umowa o pracę = UoP; B2B = własna działalność
- brutto = przed opodatkowaniem; netto = na rękę

Списки стоп-слов и синонимов **правятся в админке**, версия, тест на примере (раздел 9).

### 5.6. Регионы, города, районы, индексы

- **16 воеводств:** dolnośląskie, kujawsko-pomorskie, lubelskie, lubuskie, łódzkie, małopolskie, mazowieckie, opolskie, podkarpackie, podlaskie, pomorskie, śląskie, świętokrzyskie, warmińsko-mazurskie, wielkopolskie, zachodniopomorskie.
- Города по справочнику **TERYT / SIMC** (код + название + воеводство + powiat), у больших городов районы (dzielnice): Warszawa (Mokotów, Praga-Południe, Wola…), Kraków (Stare Miasto, Krowodrza, Nowa Huta…), Wrocław, Gdańsk, Poznań, Łódź.
- Ввод города свободным текстом принимается только если он однозначно сопоставляется с записью справочника (как сейчас сделано в нашем сервисе для Кореи), иначе подсказки.
- Почтовый индекс формата **NN-NNN**; поиск по префиксу (`31-` = район Кракова), соответствие индекс → город через справочник PNA. Индекс только фильтр, не показывается человеку в карточке полностью (по умолчанию показывается город и район).

### 5.7. Валюта и цена

- Валюта единственная: **PLN (zł)**, значения целые в злотых (для мелких вещей допускаются гроши, `price_pln` хранится в грошах).
- Форматы отображения: «4 500 zł» (пробел как разделитель тысяч), «45,50 zł»; «od 4 000 do 6 000 zł» для диапазона.
- Типы: сумма, «do negocjacji» (договорная), «za darmo / oddam» (бесплатно). Договорная участвует в фильтре цены, если включён тип «договорная» (по умолчанию включена); бесплатная имеет цену 0 и **не** смешивается с «цена не указана».
- Для работы: период `zł/mies.`, `zł/godz.`, `zł/szt.`; **brutto / netto** отдельным полем; фильтр зарплаты по нормализованному значению в месяц (при `zł/godz.` × 168 ч, правило настраивается).
- Запрос с числами разбирается: «do 3000» → цена ≤ 3000; «od 2500» → ≥ 2500; «2000-3000» → диапазон; «3 tys.» → 3000.

## 6. Поиск в знакомствах (отдельно)

### 6.1. Фильтры

Подробности:

| Фильтр | Правило |
|---|---|
| Возраст | 18–99; **нельзя** задать нижнюю границу < 18 ни в интерфейсе, ни в запросе (сервер обрезает); считается от даты рождения на дату запроса |
| Пол анкеты / кого ищет | значения: `мужчина`, `женщина`, `другое`; сочетание задаёт «подходит под мои предпочтения»; по умолчанию учитываются предпочтения зрителя из профиля, фильтр можно снять |
| Город | город → воеводство → страна (раздел 4.3), для знакомств по умолчанию **не расширять автоматически**, а предлагать кнопкой |
| Цель | множественный выбор |
| Документ / виза | множественный, по справочнику раздела 5.8 |
| Параметры | рост, дети, курение, языки (только то, что включено в конструкторе анкеты) |
| Фото | «только с публичным фото» включён по умолчанию |

### 6.2. Приватные фото

- Хранятся **отдельно** от публичных (другое хранилище, другой доступ), в индексе только `private_photo_count`.
- В выдаче и карточке: публичное фото, затем замок «🔒 3 prywatne zdjęcia — dostępne z VIP» (или кнопка «Odblokuj» для зрителя без VIP).
- Просмотр: зритель с активной услугой VIP получает **короткоживущие подписанные ссылки** (60 секунд, привязаны к зрителю), проверка права **при каждой выдаче ссылки**, а не при загрузке списка.
- Миниатюры приватных фото не создаются публично; водяной знак с идентификатором зрителя в большом размере (необязательно, снижает утечки).
- В индекс, карту сайта, ленту, бот и уведомления приватные фото **не попадают никогда**.
- Если VIP закончился, ссылки перестают выдаваться сразу.
- Любая жалоба на приватное фото направляется сотрудникам, у них доступ только по роли и записывается в журнал.

### 6.3. «Невидимка»

- Флаг `invisible = true` исключает анкету из: поиска, списков, «новых», рекомендаций, `/find` в боте, уведомлений по сохранённым поискам и карты сайта.
- Анкета остаётся доступной **по прямой ссылке** с токеном (`/p/<id>?k=<токен>`), страница с `noindex`; владелец сам распространяет ссылку.
- Владельцу в кабинете виден статус «Niewidoczna» и предупреждение, что ссылка доступна всем, у кого она есть.
- Без лайков и матчей «невидимка» не ломает логику, так как взаимодействия между анкетами нет; единственный побочный эффект: сохранённые поиски зрителей перестают сообщать о ней.
- Окончание услуги возвращает анкету в выдачу автоматически, о возврате уведомление владельцу.

### 6.4. VIP

- Прибавка к рангу + метка «VIP» в карточке, подчиняется правилу «5 / 2» и лимиту 30 % (раздел 3.2).
- VIP **не обходит** фильтры (возраст, пол, город, документы) и **не показывается** там, где человек не подходит под условия.
- Не более **1** VIP-анкеты на 4 позиции; метка всегда видна, скрытая реклама запрещена.
- Для владельца видна статистика «просмотры за VIP-период», без пересчёта «упущенного».

### 6.5. Безопасность

| Угроза | Мера |
|---|---|
| Несовершеннолетние | жёсткое правило `age ≥ 18` в индексе и в запросе; дата рождения не меняется свободно (одна правка, потом через поддержку); анкета при подозрении (жалоба «minor») мгновенно скрывается до проверки; фото модерируются |
| Фейки | сигналы: одинаковое фото у разных анкет (perceptual hash), много анкет с одного устройства или IP, быстрое создание и удаление, контакты в тексте, стоковые фото, расхождение возраста и фото, отсутствие подтверждения; результат: пометка для модератора, штраф −15 в ранге, ограничение показа |
| Жалобы | 1 жалоба = штраф в ранге и очередь модерации; ≥ 2 разных жалующихся по причинам «fake / minor / fraud» = **автоскрытие** до решения; подтверждение → блокировка; повторные ложные жалобы от одного человека ограничиваются |
| Подтверждение | бейдж «Zweryfikowana» (селфи) даёт доверие в ранге, не обязателен |
| Утечка | приватные фото и контакты не в индексе, не в логах, не в уведомлениях бота |

Без матчей и лайков связь между людьми идёт **вне** анкеты (в условии не определено, см. раздел 12).

## 7. Сохранённые поиски и подписки

| Вопрос | Решение |
|---|---|
| Что сохраняется | `doc_type`, текст запроса, все фильтры, локация (город или воеводство), сортировка, язык интерфейса; **имя** (по умолчанию из запроса, переименовывается) |
| Подписка | режим «сразу» (по умолчанию) или «сводка раз в сутки в 09:00 по времени пользователя» |
| Частота «сразу» | не чаще **1 сообщения на поиск в 15 минут** (новые за окно объединяются: «3 nowe ogłoszenia») и не больше 10 сообщений в сутки суммарно; остальное в сводку |
| Источник правды | событие «объект стал видимым» → сопоставление с сохранёнными поисками (проверка фильтров на новой записи) → запись в таблицу уведомлений → доставка на сайт (центр уведомлений) и в бот; **одна запись, два канала**, бот и сайт не считают самостоятельно |
| Что не уведомляет | свои объекты автора, скрытые и невидимые, объекты, которые не подходят под сохранённые фильтры на момент публикации; правка уже опубликованного не уведомляет |
| Лимит | **10** сохранённых поисков на человека суммарно по типам |
| Пауза | поиск не проверяется, события за паузу не копятся и не приходят после снятия |
| Удаление, переименование | в любой момент, удаление сразу прекращает уведомления |
| Автопауза | 90 дней без открытия уведомлений: поиск ставится на паузу с вопросом «Nadal szukasz?» |
| Знакомства | уведомление **без фото и имени**: «Nowa osoba pasuje do Twojego wyszukiwania» + число, подробности только внутри сайта |
| Если ничего нет | в списке сохранённых: «Brak nowych od ostatniej wizyty»; при сохранении: «Zapisano. Damy znać, gdy pojawi się coś nowego» + «Pokaż teraz» |

## 8. Пустые состояния и ошибки

| Ситуация | Что видит человек |
|---|---|
| Объявления: ничего не найдено | «Nic nie znaleźliśmy dla „…”.» Кнопки: «Wyczyść filtry», «Szukaj w całej Polsce», «Powiadom mnie» (сохранить поиск), список «Podobne» (по категории) |
| Анкеты: ничего | «Brak profili spełniających kryteria.» Кнопки: «Rozszerz wiek», «Zmień miasto», «Powiadom mnie» (без показа имён) |
| Резюме: ничего | «Brak kandydatów.» Кнопки: «Zmniejsz wymagania», «Dodaj ogłoszenie o pracę» |
| Отзывы: ничего | «Brak opinii» с пояснением, как оставить отзыв |
| Заявки (админ): ничего | «Brak zgłoszeń w tej kolejce» |
| Слишком узкие фильтры | Выбирается до **3 фильтров**, снятие которых даёт больше всего результатов, показывается «Bez filtra „Cena” znajdziesz 38 ogłoszeń» кнопками |
| Пуст город | Блоки: воеводство, затем страна; плашка с объяснением (раздел 4.3) |
| Опечатка | «Wyniki dla: **spawacz**» + «Szukaj dokładnie: …» (раздел 5.3) |
| Запрос кириллицей, контент на латинице | поиск выполняется по соответствиям (5.4); если ничего, подсказка «Spróbuj po polsku: „praca”» |
| Запрос на польском, контент на русском | то же в обратную сторону, подсказка «Спробуйте російською: „робота”» (на языке интерфейса) |
| Ошибка поиска | «Wyszukiwanie chwilowo niedostępne. Spróbuj ponownie», кнопка «Spróbuj ponownie», код ошибки; ошибка автоматически уходит в журнал |
| Нет связи | «Brak połączenia» и последние закэшированные результаты, помеченные «Zapisane wyniki» |
| Слишком короткий запрос (1 символ) | подсказка «Wpisz co najmniej 2 znaki», без запроса к индексу |

## 9. Что админка должна управлять в поиске

| Настройка | Где | Как работает |
|---|---|---|
| Фильтр, карточка, поиск по полю | конструктор полей категории: три флажка «использовать как фильтр», «показывать в карточке», «использовать в поиске» | применяется после **переиндексации** (кнопка), без релиза |
| Доступные сортировки | настройки типа контента: включено/выключено, порядок, сортировка по умолчанию | применяется сразу |
| Бейджи | список (VIP, Zweryfikowany, Nowe, Przypięte, Podbite), у каждого условие, цвет, **приоритет показа** (на карточке не больше 2 бейджей, остальные в карточке объекта) | сразу |
| Правила ранжирования | веса: текст (по умолчанию 40), свежесть (25), локация (15), доверие (10), платность (10), штрафы (жалоба −10/−5, флаги −10…−20); периоды полураспада по категориям; лимиты платных («окно 5 / максимум 2», «30 %», «закреплённых 2», «автор в топ-10 не более 2») | в черновике, проверка в «Тесте поиска», публикация по кнопке, версии и откат |
| Стоп-слова и синонимы | редактор списков, версии, импорт/экспорт CSV, пометка «односторонний» | требуют переиндексации запроса (мгновенно) и записей (в фоне) |
| Словарь польский ↔ русский/украинский | отдельная таблица терминов и транслитерации городов | сразу |
| Справочники | города, воеводства, документы (значения и порядок) | сразу |
| **Тест поиска** | поле запроса + фильтры + выбор зрителя («как видит гость / пользователь из Krakowa / сотрудник») | показывает выдачу и **объяснение ранга** по каждому объекту: вклад текста, свежести, локации, доверия, платности, штрафов, сработавшие синонимы и поправки опечатки, почему объект **не** показан (статус, срок, невидимка, жалобы) |
| Переиндексация | кнопки: объект, категория, тип, всё; статус и прогресс | в фоне, без простоя (раздел 10) |
| Откат | «Вернуться к прошлой версии индекса / настроек» | переключение алиаса индекса |
| Журнал изменений | кто и когда изменил вес, синоним, флаг поля | запись «до и после» |

Права: настройки поиска только у **Администратора и выше**, тест у **Модератора**, переиндексация у **Суперадмина**.

## 10. Связь с админкой и ботом

### 10.1. Единый слой поиска

Одна функция: `search(doc_type, query, filters, sort, page, viewer, scope)`. Возвращает объекты, число найденных, подсказки («возможно, вы имели в виду»), блоки локации и объяснение ранга (если разрешено). `viewer` задаёт язык, город, права на приватное; `scope` = `public | staff | bot`. Сайт, админка и бот **не содержат** собственных фильтров, сортировок и правил видимости.

### 10.2. Админка

- Те же фильтры и сортировки, плюс служебные: статус, флаги модерации, источник, жалобы, платное.
- Видимость отключена (`scope=staff`), видны скрытые, истёкшие, невидимки; приватные фото только по роли с записью в журнал.
- Управление индексом: переиндексация (объект, категория, тип, всё), статус индексатора, ошибки, **откат**.

### 10.3. Переиндексация без простоя

Схема blue-green: строится **новый индекс** рядом с рабочим, во время сборки новые события пишутся в оба, по готовности алиас переключается атомарно, старый индекс хранится до следующей версии для отката. Нагрузка ограничена, чтобы не тормозить сайт.

### 10.4. Бот

- Команда `/find <запрос>`: до **5** результатов, у каждого название, цена, город, бейдж, кнопка «Открыть» (диплинк `?start=l_<id>`), «Pokaż więcej na stronie» с переходом на сайт с теми же фильтрами.
- Поддерживает только **город и цену**: `/find praca Kraków do 5000`; остальное на сайте.
- Использует тот же слой поиска со `scope=bot`: те же видимость, ранг и лимит платных (в 5 результатах не более 1 платного).
- Бот **не показывает** приватные фото, контакты, «невидимок», анкеты знакомств с фото (только текст «Znaleziono N, otwórz na stronie»).
- Бот **не делает**: полные фильтры, бесконечные списки, редактирование поисковых настроек, показ отзывов и заявок работодателей посторонним.
- Результат бота и сайта при одинаковых параметрах **совпадает** по составу и порядку (проверяется автотестом).
