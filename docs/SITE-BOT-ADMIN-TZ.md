# ТЗ на доработку: сайт, админка и Telegram-бот (без изменения структуры сайта)

**Ограничение:** страницы, разделы, URL и логика сайта не меняются. Меняется то, **как это выглядит и работает** внутри существующих страниц, и добавляются недостающие инструменты. Всё описано без привязки к стеку.

**Сквозной принцип:** источник правды один, это база сайта. Админка и бот только **клиенты** этой базы через один и тот же слой операций (одни и те же функции «одобрить», «заблокировать», «отправить уведомление»). Никакой логики, существующей только в боте или только в админке.

# БЛОК 1. Пользовательская часть сайта

## 1.1. Главная

| Что | Правка (конкретно) |
|---|---|
| Поиск | Крупная строка поиска **первым блоком** под шапкой (высота ≥ 48 px), подсказка «Что ищете? Например: сварщик, квартира, диван». Подсказки при вводе (заголовки + города), последние 8 запросов, не больше 6 подсказок. |
| Категории | Сетка плиток 2×N на телефоне (3×N на планшете): иконка 32 px + название. Не больше 9 плиток, остальное «Ещё». Плитка ведёт в тот же раздел, что и сейчас. |
| Свежее | Два блока: «Свежие» по главному разделу сайта и «Новые» по остальным, по 6 карточек, ссылка «Смотреть все» к соответствующему списку. Данные грузятся с сервера, при ожидании скелетоны, при ошибке кнопка «Повторить». |
| Город | Выбор города в шапке одним нажатием, запоминается. Выдача по умолчанию сначала по городу, потом по Корее (или иной зоне сайта). |
| Акценты | Платные и закреплённые объявления помечены значком, не больше 2 подряд. Одна цветовая акцентная кнопка на экране («Подать объявление»). |
| Доверие | Под категориями строка «Проверка объявлений модератором, жалоба в один клик». |
| Пусто | Если в городе нет объявлений: «Пока нет объявлений в Сеуле. Показать по всей стране» + кнопка «Подать первое». |

## 1.2. Категория и поиск

**Фильтры**
- Панель фильтров открывается как нижний лист на телефоне (кнопка «Фильтры (N)» с числом активных), слева колонкой на компьютере.
- Общие: город/район, цена от-до, «только с фото», «за последние 24 ч / 7 дней».
- Фильтры конкретной категории **берутся из полей категории** (отмечены «использовать как фильтр»): для работы это график, занятость, виза, жильё; для жилья тип, залог, площадь; для вещей состояние, бренд.
- Активные фильтры показаны чипами над списком, у каждого крестик, кнопка «Сбросить всё».
- Результат обновляется кнопкой «Показать N объявлений» (число считается заранее), а не при каждом клике.

**Сортировка:** «Сначала новые» (по умолчанию), «Дешевле», «Дороже», «Ближе ко мне» (если есть геолокация). Платные закрепления всегда сверху и подписаны.

**Карточка в списке** (в одну строку на телефоне, горизонтальная):
- Слева фото 1:1 (96–110 px), справа: название (до 2 строк), **цена жирным**, город · «время назад», 2–3 ключевых параметра чипами (для работы: график, жильё; для жилья: комнаты, метро).
- Бейджи: «VIP», «Проверенный автор», «Новое». Сердечко «в избранное» в углу фото, нажатие не открывает объявление.
- Нет фото: аккуратная заглушка с иконкой категории, а не пустое место.

**Пагинация:** «Показать ещё» (20 карточек за раз) и счётчик «Найдено 124». Бесконечная прокрутка не нужна: теряется место в списке. Позиция списка и фильтры сохраняются при возврате с карточки.

**Поиск:** игнорирует регистр, понимает окончания, опечатки и латиницу вместо кириллицы; при пустом результате: «Ничего не найдено по “…”. Показано по запросу “…”», кнопки «Сбросить фильтры» и «Сообщить, когда появится» (сохранённый поиск).

**Сохранённый поиск:** кнопка «Следить за поиском» (см. блок 3), у каждого можно открыть, поставить на паузу, удалить, ограничение 10 штук.

## 1.3. Карточка объявления

| Зона | Правка |
|---|---|
| Фото | Галерея на всю ширину, свайп, счётчик «3/8», нажатие открывает на весь экран с увеличением. |
| Шапка | Цена крупно, название, город · время · номер объявления, кнопка «в избранное» и «поделиться». |
| Ключевые параметры | Сетка «ярлык: значение» (2 колонки), сразу под ценой, без прокрутки до них. |
| Описание | Абзацы сохраняются, длинный текст сворачивается с «Читать полностью». |
| Автор | Блок: имя, «на сайте с …», число активных объявлений, рейтинг и отзывы, отметка «проверенный». Ссылка «Все объявления автора». |
| Связь | **Фиксированная нижняя панель** с главной кнопкой («Написать» / «Откликнуться» для вакансий) и вторичной («Позвонить» только если автор открыл телефон). Телефон не показывается без нажатия, повторные показы считаются. |
| Похожие | Блок «Похожие объявления» (та же категория и город, до 6), горизонтальная лента. |
| Жалоба | Ненавязчивая ссылка «Пожаловаться» внизу, лист с причинами (мошенничество, дубликат, неверная категория, запрещённое, другое) и необязательным комментарием; повторно пожаловаться на то же нельзя, показывается «жалоба принята». |
| Предостережение | Короткая подсказка рядом со связью: «Не переводите предоплату незнакомым людям». |
| Состояния | Снято или истекло: плашка «Объявление неактуально» + похожие, а не пустая страница 404. |

## 1.4. Форма подачи (пошагово)

Пять шагов, индикатор «Шаг 2 из 5», кнопки «Назад» и «Далее», автосохранение черновика на сервере после каждого шага.

1. **Раздел и категория** (плитки, не выпадающие списки).
2. **Фото** (до N, перетаскиванием меняется порядок, первое обложка; сжатие на устройстве, подсказка «Хорошее фото = в 3 раза больше откликов»).
3. **Название, описание, цена** (счётчик символов, пример заполнения, цена: сумма / договорная / бесплатно).
4. **Параметры категории** (только поля этой категории, обязательные отмечены ✱, понятные ошибки рядом с полем).
5. **Контакты и город**, затем **предпросмотр** (карточка как её увидят) и кнопка «Отправить на проверку».

**Правила:** обязательно минимальный набор (раздел, название, описание ≥ 30 символов, город, контакт); остальное по правилам категории. Проверки на лету (телефон в описании, ссылки, стоп-слова) с подсказкой, как исправить. После отправки экран «Объявление на проверке, обычно до суток» с кнопками «Подать ещё» и «Мои объявления».

## 1.5. Личный кабинет

- **Если не вошёл:** один экран «Войдите» с кнопкой входа и пояснением, без меню и пустых счётчиков.
- **Меню** сгруппировано: «Мои объявления», «Отклики/сообщения», «Избранное», «Сохранённые поиски», «Настройки», «Помощь».
- **Мои объявления:** вкладки по статусам (Активные, На проверке, Требуют правки, Завершённые, Черновики). Карточка: фото, название, статус с цветом, **причина отказа текстом**, срок «ещё 12 дней», кнопки по статусу.
- **Кнопки по статусу:** Изменить, Продлить (с объяснением, когда можно), Поднять / Продвинуть, Закрыть, «Продано», Удалить (с подтверждением), «Оспорить решение» для отклонённых.
- **Статистика объявления:** просмотры, добавлено в избранное, число сообщений и звонков; график за 14 дней.
- **Редактирование:** та же форма, что при подаче, с заполненными полями; пометка, какие правки уйдут на повторную проверку.
- **Уведомления:** центр уведомлений с кнопкой «прочитать всё» и настройками по видам.
- **Данные:** выгрузка и удаление аккаунта одним понятным разделом.

## 1.6. Мобильная версия (ключевые правки)

- Минимальный размер нажимаемого элемента **44×44 px**, шрифт текста ≥ 16 px (иначе iOS приближает страницу при вводе).
- Нижняя навигация из пяти пунктов (Главная, Избранное, Добавить, Сообщения, Профиль), «Добавить» выделена; не закрывает содержимое (внизу отступ равный высоте панели).
- Ничего не прокручивается вбок; таблицы превращаются в карточки; длинные слова переносятся.
- Клавиатура не перекрывает поле ввода (поле «приклеено» над клавиатурой), при открытии поле прокручивается в видимую область.
- Тяжёлое: изображения с ленивой загрузкой и миниатюрами, первая загрузка до 2,5 с на 4G.
- Жесты: «потянуть вниз» обновляет список, свайп по фото листает, системная «Назад» возвращает на прошлый экран, а не закрывает сайт.
- Всплывающие окна: свой лист снизу вместо системных `alert/confirm`, закрывается по касанию вне окна и по «Назад».

## 1.7. Общие UX-принципы

| Принцип | Конкретно |
|---|---|
| Навигация | Всегда видно, где ты: заголовок экрана, «хлебные крошки» на компьютере, кнопка «Назад» в одном месте. |
| Обратная связь | Любое действие отвечает за 100 мс (нажатие, загрузка), после действия короткое сообщение («Добавлено в избранное», «Продлено до 12.12»). Кнопка во время запроса блокируется. |
| Пустые состояния | У каждого пустого списка: что это, почему пусто, **одна кнопка действия** («Подать первое объявление»). |
| Ошибки | Человеческим языком, что случилось и что делать («Нет связи. Проверьте интернет и повторите»), кнопка «Повторить». Код ошибки в сноске, и ошибка сама отправляется на сервер (человеку не нужно присылать скриншот). |
| Гость | Просмотр без входа. Вход спрашивается только на действие («Написать»), после входа действие продолжается само. |
| Подтверждения | Только для необратимого (удалить, заблокировать), со словом действия на кнопке («Удалить»), а не «Да». |
| Доступность | Контраст текста ≥ 4,5:1, подписи у иконок, размер текста настраивается. |
| Скорость | Скелетоны вместо спиннеров, кэш последних списков для открытия при плохой связи. |
| Версия | Номер версии сайта в подвале и в `/health`; страница сама обновляется при выходе новой (нет «устаревших копий»). |

## 2.3. Роли (сжато)

| Действие | Поддержка | Модератор | Админ | Суперадмин |
|---|---|---|---|---|
| Очереди и ответы, блок до 7 дней | да | да | да | да |
| Решения по объявлениям, правка текста, заметки, блок до 30 дней | нет | да | да | да |
| Категории, контент, цены, платежи, рассылки, антиспам | нет | чтение | да | да |
| Журнал | нет | свои | да | да |
| Сотрудники, права, системные настройки, удаление данных | нет | нет | нет | да |

Права проверяются **на сервере**; роль + исключения по сотруднику; нельзя менять свою роль, блокировать себя, решать собственное дело.

## 2.4. Сценарии (сжато)

- **Модерация:** взять следующее → предпросмотр + флаги + история автора → при нужде правка → решение (одобрить / на доработку / отклонить / скрыть и заблокировать) с причиной из шаблона → автору уведомление → запись в журнал → отмена 30 минут.
- **Жалоба:** жалобы собраны по объекту → объект скрывается автоматически при ≥ 3 разных жалующихся → принять / принять и заблокировать / отклонить / отклонить как злоупотребление → жалующемуся ответ.
- **Бан:** срок (1, 3, 7, 30, бессрочно) + причина для сотрудников + текст человеку + судьба объявлений → блок сам снимается по сроку → оспаривание из приложения.
- **Категории:** дерево → конструктор полей (тип, обязательность, фильтр, поиск, в карточке) → правила (фото, срок, лимиты, предмодерация) → предпросмотр формы → сохранить (для новых объявлений) → мастер переноса объявлений.

# БЛОК 3. Telegram-бот в связке с сайтом и админкой

## 3.1. Роль бота

Бот это **второй вход и канал уведомлений**, а не копия сайта. Он делает то, что **удобнее в мессенджере**: короткие уведомления, быстрые решения одной кнопкой, вход и привязка аккаунта. Подробное (длинные формы, фото, фильтры, настройки) остаётся на сайте и открывается кнопкой «Открыть на сайте» (Mini App или ссылка).

## 3.2. Функции для пользователей

| Функция | Как работает |
|---|---|
| **Привязка аккаунта** | Кнопка «Войти через Telegram» на сайте → открывается бот с токеном → «Это я, войти» → сайт входит сам. Один аккаунт = один Telegram ID. Отвязка и смена в настройках; при смене нужен вход со старого. |
| **Уведомления о сообщениях** | «Борис пишет по объявлению «Диван»: текст…» + кнопка «Ответить» (открывает чат на сайте или отвечает прямо в боте). Одно сообщение на диалог в минуту, чтобы не засыпать. |
| **Статус объявлений** | «Одобрено», «Отклонено: причина», «Требует правки», «Срок заканчивается через 3 дня» с кнопкой «Продлить» (быстрое действие в боте). |
| **Сохранённые поиски** | Подписка «Следить за поиском» → «Новое по вашему поиску: 3 объявления» (сводка раз в сутки или сразу, на выбор) + кнопка «Смотреть». |
| **Отклики (для вакансий)** | Работодателю: «Новый отклик на «Сварщик»» + кнопки «Пригласить / Отказать». Кандидату: «Вам ответили: приглашение / отказ». |
| **Избранное** | «Цена снизилась на «Диван»» с кнопкой «Открыть». |
| **Поиск в чате** | Команда `/find слово` и кнопки разделов с короткими карточками (название, цена, город, «Открыть»). Максимум 5 результатов, дальше «Показать на сайте». |
| **Просмотр объявления** | Ссылка вида `t.me/бот?start=l_123` показывает карточку и кнопку «Открыть на сайте». |
| **Подача через бота** | Только **быстрый старт**: «Подать объявление» → выбор раздела → название → цена → фото (1–3) → «Дополнить на сайте». Черновик сохраняется в базе, на сайте открывается заполненная форма с четвёртого шага. Полная форма не дублируется. |
| **Жалоба** | В карточке в боте кнопка «Пожаловаться» → причина кнопкой → «Принято». |
| **Платежи** | Счёт на платные услуги и квитанция (если платёж идёт через Telegram). |
| **Настройки уведомлений** | `/settings`: включить или выключить по видам (сообщения, отклики, решения, поиски, сроки, платежи), тихие часы, режим «сводка раз в сутки». Основное выключение остаётся на сайте. |
| **Поддержка** | `/help` + «Написать в поддержку» создаёт обращение в той же очереди, что и сайт; ответ приходит сюда и в приложение. |

## 3.3. Функции для сотрудников (бот и админка вместе)

Сотрудник привязывает Telegram в панели (одноразовый код). Бот узнаёт его **по Telegram ID из списка сотрудников**, роль берётся оттуда же.

| Функция | Как работает |
|---|---|
| **Вход в админку** | Код или кнопка подтверждения в боте (двухфакторная защита); новый вход показывает устройство и город, кнопка «Это не я» завершает все сессии. |
| **Уведомления об очередях** | «Новое объявление на проверку (N в очереди)», «Новая жалоба», «Новое обращение». Не чаще одного сообщения на вид в 10 минут, с кнопкой «Открыть очередь». Настраивается: какие виды, тихие часы, дежурство. |
| **Модерация в боте** | Карточка объявления (фото, название, цена, город, автор, флаги, автор с историей) и кнопки **✔ Одобрить / ✏ На доработку / ✖ Отклонить / 🚫 Заблокировать / ➡ Следующее**. Для отказа бот предлагает **шаблоны причин** кнопками (те же, что в админке) или ввод своего текста. |
| **Жалобы** | Карточка жалобы с объектом, причинами и кнопками «Принять / Отклонить / Заблокировать автора». |
| **Блокировки** | `/ban ID 7д причина`, снять `/unban ID`. Бессрочные только с роли «Администратор». |
| **Обращения** | Ответить на обращение прямо в боте (reply на сообщение). |
| **Срочное** | Предупреждения о сбоях: «Сайт не отвечает», «Бот не отвечает», «Диск заканчивается», «Всплеск ошибок». |
| **Сводка** | `/stats`: очереди, публикации, жалобы, выручка за сутки. |
| **Рассылки** | Только создание черновика и запуск с подтверждением числа получателей; сложные настройки в панели. |

**Безопасность решений в боте:**
- Кнопки несут **подписанные одноразовые данные** (идентификатор действия + объект + срок действия + подпись). Нажатие старой кнопки: «Это решение уже принято» (идемпотентность).
- Перед выполнением сервер заново проверяет **роль** и **состояние** объекта (не решено ли уже, не взято ли другим сотрудником).
- Любое решение пишется в тот же **журнал**, что и из админки (канал: «бот»), и его можно **отменить** 30 минут из админки или кнопкой «Отменить» в боте.
- Решение, которое меняет много данных (бессрочный блок, массовое), в боте **не выполняется**, а даёт ссылку «Открыть в панели».

## 3.4. Что синхронизируется

Единственный источник правды: база сайта. Бот и админка читают и пишут через общий слой операций.

| Данные | Направление | Как |
|---|---|---|
| Привязка Telegram ↔ аккаунт | сайт ↔ бот | Таблица `telegram_links` (user_id, telegram_id, привязан, когда, последний ответ бота) |
| Статус объявления | админка / бот → сайт | Одно действие «решение», один результат везде; сайт и бот показывают одинаковый статус |
| Уведомления | сайт → бот | Таблица `notifications` (всегда пишется), потом доставка в Telegram по настройкам человека; статус доставки (доставлено, ошибка, бот заблокирован) |
| Настройки уведомлений | сайт ↔ бот | Таблица `notification_prefs`, общая; изменение в боте видно на сайте и наоборот |
| Очереди и счётчики | сайт → админка / бот | Читаются из базы, не копируются |
| Сохранённые поиски | сайт ↔ бот | Одна таблица, у каждого признак «уведомлять» и режим (сразу / сводка) |
| Черновик, начатый в боте | бот → сайт | Таблица черновиков по пользователю, сайт продолжает с нужного шага |
| Журнал действий | админка + бот → журнал | Одна запись на действие, поле «канал» (сайт / админка / бот) |
| Сотрудники и роли | админка → бот | Бот сверяет Telegram ID с `staff` на каждом действии, кэша прав нет |
| Рассылки | админка → бот | Очередь получателей, бот отправляет порциями, в ответ пишет статус |
| Ошибки доставки | бот → админка | Лог доставки, счётчик «бот заблокирован пользователем», раздел «Состояние системы» |

**Надёжность доставки:** шаблон «outbox» (запись «надо отправить» создаётся в той же транзакции, что и событие, отправитель берёт её и повторяет с паузой; после 5 неудач помечает «не доставлено»). Если пользователь заблокировал бота, уведомление остаётся в центре уведомлений на сайте, и сервис больше не пытается писать в Telegram, пока человек сам не вернётся.

## 3.5. Деплой и режимы

- Приём событий: **webhook** (быстрее и не теряет события) или long polling, если нет публичного адреса. Один способ в один момент, при старте бот снимает чужой webhook.
- Бот работает отдельным процессом, общая база с сайтом; **пульс** (метка «жив») пишется раз в минуту, панель показывает «бот отвечает N с назад», при тишине > 5 минут сотрудникам приходит предупреждение.
- Лимиты Telegram (~30 сообщений в секунду всего, 1 в секунду в один чат) соблюдаются очередью отправки; рассылка идёт порциями.
- Токен только в окружении сервера, не в репозитории и не в логах; при утечке токен меняется в одном месте.

## 3.6. Что бот НЕ должен делать

| Не делает | Почему и что вместо этого |
|---|---|
| Полная форма подачи со всеми полями | Дублирует сайт и ломает проверки. Быстрый старт + «Дополнить на сайте». |
| Каталог с фильтрами и бесконечными списками | Неудобно в чате. До 5 результатов + «Открыть на сайте». |
| Чат между людьми как основной канал | Переписка живёт на сайте (история, жалобы, блокировки). В бот приходят уведомления и короткий ответ-быстро; важное связывается с сайтом. |
| Показывать телефоны и контакты в чате | Контакты показываются только на сайте по нажатию, с учётом настроек автора. |
| Массовые и необратимые решения | Бессрочные блокировки, массовое удаление, смена цен и ролей только в панели. |
| Хранить свою копию данных или правил | Только читает и пишет в общую базу, без своих списков и кэша прав. |
| Рассылка без подтверждения | Всегда «Получателей: N. Отправить?». |
| Присылать лишнее | Не больше одного сообщения о событии одного вида за окно (10 минут для сотрудников, 1 минута на диалог для пользователей); есть тихие часы и «сводка раз в сутки». |
| Принимать оплату и возвраты вне общего слоя платежей | Все платежи и возвраты проходят через одну логику, видимую в админке. |
| Хранить паролей и вход без подтверждения | Вход только через подтверждение в Telegram на самом аккаунте. |

## 3.7. Команды и ссылки

| Команда | Кому | Что |
|---|---|---|
| `/start` | все | Меню разделов, кнопка «Открыть сайт» |
| `/find слово` | все | Быстрый поиск, до 5 результатов |
| `/my` | все | Мои объявления и статусы |
| `/settings` | все | Уведомления по видам, тихие часы |
| `/help` | все | Справка, связь с поддержкой |
| `/admin` | сотрудники | Очереди, сводка, решения |
| `/ban`, `/unban` | сотрудники | Блокировки на срок |
| `/stats` | админ | Сводка за сутки |

Диплинки: `?start=l_<id>` объявление; `?start=login_<токен>` вход на сайте; `?start=src_<метка>` источник трафика; `?start=ref_<код>` приглашение; `?start=ticket_<id>` обращение.
