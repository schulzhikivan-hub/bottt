## 1. Цели и результат MVP

Цель: рабочий прототип с основными функциями для первых пользователей (задание №1).

Результат, который проверяется:
- пользователь открывает бота, попадает в Mini App и публикует вакансию, объявление или товар;
- модератор одобряет или отклоняет публикацию из админ-панели;
- пользователи находят публикации по фильтрам и пишут друг другу во внутреннем чате;
- владелец может поднять или закрепить публикацию за Stars;
- все пять основных разделов работают на iPhone и Android.

## 2. Роли и права

| Роль | Как получается | Права |
|---|---|---|
| Гость | Открыл бота, но не нажал «Начать» | Видит приветственный экран и ссылку на Mini App. Публикаций не видит. |
| Пользователь | Запустил Mini App, принял соглашение | Смотрит публикации, избранное, пишет в чат, публикует объявления в своих разделах. |
| Работодатель | Пользователь с заполненным профилем компании и прошедший проверку модератором | Публикует вакансии без проверки цены (кроме платных услуг), видит отклики. |
| Модератор | Назначается администратором | Очередь модерации, жалобы, блокировка публикаций. Не видит платёжные данные. |
| Администратор | Назначается Super Admin | Всё, кроме управления ролями. Цены, справочники, статистика, платежи. |
| Super Admin | Один или два человека | Роли, системные настройки, аудит. |

Правила:
- Роль проверяется на сервере при каждом запросе (как в ТЗ v1.0 §3.1).
- Админка доступна только по allowlist Telegram ID и только через Mini App или веб-вход по коду из бота.
- Блокировка пользователя скрывает его публикации и запрещает новые действия, но не удаляет историю платежей.

## 3. Вход и авторизация

### 3.1. Первый запуск
1. Пользователь нажимает `/start` в боте.
2. Бот показывает приветствие из экрана 1 макета и кнопку «Открыть приложение».
3. Бот создаёт запись пользователя по Telegram ID, если её нет. Язык выбирается по `language_code` из Telegram; если языка нет в списке, то английский.
4. Mini App открывается. Фронтенд передаёт `initData` на сервер.
5. Сервер проверяет подпись `initData` по токену бота (HMAC-SHA256) и срок действия (не старше 24 часов).
6. Выдаётся сессия (JWT или cookie, срок 7 дней, обновление при активности).

### 3.2. Онбординг (обязательный, один раз)
- Шаг 1: выбор языка интерфейса (экран 13 макета, список из 9 языков).
- Шаг 2: выбор города и района из справочника (§10.3).
- Шаг 3: принятие пользовательского соглашения и политики конфиденциальности (отдельные галочки, ссылки открываются внутри Mini App).
- Шаг 4 (необязательно): имя для профиля, фото, контакт (телефон или Telegram-username, см. §7.2).

Пропустить можно только шаги 1–2 с городом по умолчанию (Сеул). Шаг 3 обязателен.

### 3.3. Команды бота
| Команда | Действие |
|---|---|
| `/start` | Приветствие и кнопка открытия Mini App |
| `/help` | Поддержка и ссылка на правила |
| `/lang` | Смена языка |
| `/my` | Мои публикации (ссылка в Mini App) |
| `/support` | Обращение в поддержку |

Deep links: `t.me/<bot>/app?startapp=<code>` открывает конкретный раздел или публикацию (например, `job_123`). Используется в уведомлениях и при шаринге.

### 3.4. Выход и удаление
- «Выйти» завершает сессию на устройстве, данные не удаляются.
- «Удалить аккаунт» — см. §7.4.

## 5. Дизайн-система

Дизайн должен соответствовать макету: тёмно-синяя навигация, светлый контент, яркие цветовые плитки категорий, карточки с фото и тегами, крупные зелёные и синие кнопки. Значения ниже подобраны по макету «на глаз» и должны быть подтверждены дизайнером по исходным файлам.

- Основной текст: 15 px, regular.

- Цена: 17 px, bold, валюта после числа, разделитель тысяч — пробел (`2 800 000 ₩/мес`).

### 5.3. Размеры и отступы

- Сетка: отступы экрана 16 px.
- Шаг отступов: 4, 8, 12, 16, 24.
- Радиус карточек: 12 px; кнопок: 12 px; чипов и тегов: 999 px (пилюля); аватаров: круг.
- Высота нижней навигации: 64 px + safe area.
- Кнопка «+» в навигации: круг 52 px, поднят над панелью на 12 px.
- Минимальная высота касания: 44 px.

### 5.5. Состояния

Каждый список и экран имеет четыре состояния: загрузка (скелетоны по форме карточки), пусто (иллюстрация и кнопка действия), ошибка (текст и «Повторить»), нормально. Кнопка отправки блокируется на время запроса.

### 5.6. Анимации и обратная связь

- Переходы между экранами: 200–250 мс, без сложных эффектов.
- Нажатие: лёгкое затемнение, в Telegram — вибрация (`hapticFeedback`) на успешные действия.
- Кнопки Telegram: использовать `MainButton` для главного действия экрана (например, «Опубликовать») и `BackButton` для возврата.

### 5.7. Иконки и изображения

- Иконки — линейные, 24 px, в стиле макета. Пиктограммы категорий — заливка белым на цветном фоне.
- Фото публикаций: JPG, PNG, WebP; сжатие до 1280 px по длинной стороне; миниатюры 400 px.
- Флаги стран — иконки 24 px (экран 13).

## 6. Функционал по разделам

### 6.1. Главная (S02, S03)
- Баннер: один активный промо-блок из админки.
- Поиск: один запрос по вакансиям, жилью, товарам. Подсказки из истории и популярных запросов. Опечатки: нечёткий поиск (`pg_trgm`).
- Плитки разделов: открывают S04, S07, S10, S13, S16, S18 и т. д.
- Блок «Популярные вакансии»: 5 карточек с наибольшим числом откликов за неделю, VIP сверху.
- Блок «Новое»: последние одобренные товары.

### 6.2. Работа (S04–S06, S33)

Список:
- Фильтры: город, район, зарплата (от–до), график (полный день, сменный, неполный), жильё (да/нет), питание (да/нет), виза (E-9, F-4 и др. из справочника), тип работы.
- Сортировка: VIP сверху, затем по дате поднятия.
- Карточка: фото, должность, компания, зарплата, город, теги.

Карточка (S05):
- Галерея фото (до 10), название, компания, адрес (район), график, жильё и питание, выплаты, требования к визе, описание, дата публикации.
- Кнопки: «Написать» (открывает диалог в чате, S25) и «Позвонить» (показывает телефон, если работодатель его указал; см. §7.2).
- Отклик: отправка через «Написать» с автоматическим сообщением «Отклик на вакансию», в диалоге указана ссылка на вакансию. Отдельной кнопки «Откликнуться» в MVP нет, отклики — это диалоги.

Создание (S06):
- Поля: название, компания, город и район, зарплата (сумма и валюта), график, жильё (да/нет), питание (да/нет), требования к визе, описание (до 2000 символов), фото (до 10).
- Условия: публикация возможна только при заполненных обязательных полях; у работодателя без подтверждённого профиля публикация уходит в модерацию.
- Статус после публикации: `pending` → `published` (§8).

### 6.3. Жильё (S07–S09)

- Фильтры: город, район, цена (от–до), депозит, количество комнат, тип (квартира, комната, студия), тип договора, мебель, животные.
- Карточка: фото, цена, депозит, площадь, комнаты, этаж, коммунальные платежи, условия, район, контакт.
- Создание: название, тип, город, район, адрес или приблизительный район (точный адрес не публикуется), цена, депозит, коммунальные платежи, площадь, комнаты, этаж, условия, фото (до 10), контакт.
- Предупреждение при публикации: «Платформа не проверяет право собственности и полномочия арендодателя».

### 6.4. Барахолка (S10–S12)

- Категории: телефоны, мебель, техника, авто, одежда, детские товары, инструменты, разное (иконки из экрана 7).
- Фильтры: категория, город, цена (от–до), состояние (новое, б/у).
- Создание: название, категория, цена или «Бесплатно», состояние, город, описание, фото (до 10), способ связи.
- Торг: флаг «Торг возможен», без автоматических предложений цены.
- Статус «Продано» — кнопка владельца, публикация уходит в архив через 30 дней.

### 6.5. Знакомства (S13–S15)

Ограничения, без которых модуль не выпускается:
- Только 18+. Дата рождения вводится при создании анкеты, сервер проверяет возраст. Младше 18 — отказ без сохранения.
- Фото анкеты проходит модерацию до показа. До одобрения анкета видна только её автору.
- Номер телефона и Telegram-username в анкете не показываются. Общение — только через внутренний чат.
- Лента: вкладки Все / Девушки / Парни, фильтры город и возраст. В ленте не показываются заблокированные и уже лайкнутые анкеты.
- Лайк: сердечко. Написать в чат можно только при взаимном лайке. Кнопки «Написать» без взаимного лайка в MVP нет.
- Жалоба и блокировка доступны на каждой анкете.
- Анкету можно скрыть или удалить в любой момент.

### 6.6. Сообщество (S16, S17)

- Список групп: название, национальность или город, флаг, число участников (по данным Telegram-группы, обновляется раз в сутки), описание.
- Переход: кнопка «Перейти в Telegram-группу» открывает ссылку. Ссылки на группы добавляет админ.
- Лента постов, комментарии и лайки — этап 2 (A5).

### 6.7. Информация: Услуги, Автомобили, Документы (S18, S19)

- Список статей по разделам, поиск внутри раздела.
- Каждая статья: заголовок, краткое описание, дата публикации, дата проверки, источник (ссылка на официальный сайт). Статьи про визы и документы показывают предупреждение, если дата проверки старше 6 месяцев.
- Статьи создаёт контент-менеджер через админку (§12).

### 6.8. Профиль (S20, S21, S22, S26–S31)

- Шапка: аватар, имя, город, верификация (синяя галочка — для работодателя с подтверждённой компанией).
- Статистика: публикации, отклики, избранное.
- Пункты (как экран 10): Мои публикации, Мои отклики, Избранное, Сообщения (бейдж непрочитанных), Уведомления, Настройки, Помощь, Выйти.
- Мои публикации: статусы (§7.1), кнопки «Редактировать», «Поднять», «Закрепить», «Закрыть», «Удалить».
- Настройки: язык, город, уведомления (по типам, §6.11), приватность (показывать ли телефон и Telegram-username), удаление аккаунта, выгрузка данных.

### 6.9. Избранное (S23)
- Вкладки по типам: Вакансии, Жильё, Товары, Анкеты, Группы.
- Удаление из избранного не удаляет объект.
- Если объект удалён или снят с публикации, в избранном он показывается с серой подписью «Недоступно».

### 6.10. Чаты (S24, S25)

- Список диалогов: аватар, имя, последнее сообщение, время, непрочитанные.
- Диалог: текст (до 2000 символов), фото (до 5 шт., до 5 МБ каждое), системные сообщения (например, «Объявление снято с публикации»).
- Создаётся при первом «Написать». Одна пара пользователей — один диалог на публикацию (или на анкету).
- Действия: заблокировать собеседника, пожаловаться, очистить историю у себя (история у второго участника остаётся).
- Ограничения: не больше 30 сообщений в минуту от одного пользователя; при спаме — временная блокировка отправки.
- Уведомление о новом сообщении в Telegram-бот, если пользователь не открыт в Mini App.

### 6.11. Уведомления

| Событие | Канал | Получатель |
|---|---|---|
| Новое сообщение в чате | Бот + внутри приложения | Получатель |
| Публикация одобрена | Бот + внутри | Автор |
| Публикация отклонена (с причиной) | Бот + внутри | Автор |
| Запрошено исправление | Бот + внутри | Автор |
| Новый отклик на вакансию | Бот | Работодатель |

## 7. Общие правила

### 7.1. Статусы публикации

| Статус | Значение | Переходы |
|---|---|---|
| `draft` | Черновик | → `pending` |
| `pending` | На модерации | → `published`, `rejected`, `needs_fix` |
| `needs_fix` | Модератор запросил исправление | → `pending` (после правок) |
| `published` | Опубликовано | → `hidden`, `closed`, `sold`, `archived` |
| `rejected` | Отклонено с причиной | → `draft` (правка и повторная отправка) |
| `hidden` | Скрыто владельцем или модератором | → `published` (владелец), → `blocked` (модератор) |
| `closed` | Вакансия закрыта или объявление снято | → `archived` |
| `sold` | Товар продан | → `archived` |
| `archived` | В архиве, не в выдаче | Переход в `draft` для повторной публикации |
| `blocked` | Заблокировано модератором | Только модератор может вернуть |

Публикация в статусе `archived` не возвращается в `published` напрямую, а проходит модерацию как новая (правило из ТЗ v1.0 §31).

Публикация автоматически уходит на повторную модерацию при изменении: заголовка, цены, фото, контакта, категории.

### 7.2. Контакты и приватность

- Телефон и Telegram-username владелец публикации указывает сам. По умолчанию показываются только в карточке, которую открыл вошедший пользователь.
- Номер телефона не отображается в тексте описания: автоматическая проверка ищет телефонные номера в описании и просит убрать их или перенести в поле контакта.
- Адрес жилья — только район, точный адрес по запросу через чат.
- В знакомствах контакты скрыты полностью (§6.5).
- Если работодатель не указал телефон, кнопка «Позвонить» скрыта.

### 7.3. Персональные данные (PIPA)

- Согласие на обработку данных — при онбординге (§3.2), с указанием цели и срока хранения.
- Сроки хранения: данные аккаунта — пока аккаунт активен; сообщения — 12 месяцев после последнего сообщения в диалоге; логи — 90 дней; платёжные записи — по требованиям бухгалтерского учёта (хранится без персональных данных сверх ID).
- Удаление аккаунта: кнопка в настройках, подтверждение. Аккаунт деактивируется сразу, публикации скрываются. Персональные данные удаляются в течение 30 дней. Платёжная история сохраняется в обезличенном виде.
- Выгрузка данных: JSON-файл с профилем, публикациями и историей платежей, готовится в течение 3 рабочих дней.
- Фото людей в знакомствах и вакансиях — согласие владельца фото подтверждается галочкой при загрузке.
- Аналитика: без имён, телефонов и текстов сообщений.

### 7.4. Жалобы

Причины: мошенничество, поддельная публикация, спам, оскорбления, неприемлемый контент, нарушение прав, несовершеннолетний, жалоба на анкету.

Правила:
- Один пользователь не может подать больше 5 жалоб в сутки и повторно жаловаться на один объект.
- Жалобы на один объект объединяются. При 3 жалобах от разных пользователей публикация автоматически скрывается до решения модератора.
- Модератор видит историю и решает: скрыть, заблокировать, отклонить жалобу. Результат сообщается обоим.

## 8. Модерация и правила контента

### 8.1. Автоматические проверки (до публикации)
- Обязательные поля и формат (цена — число, зарплата не отрицательная, фото MIME-типа JPG/PNG/WebP).
- Стоп-слова и шаблоны: запросы предоплаты, «перевод на карту/счёт», «USDT», «заплатите за визу», «быстрые деньги без опыта».
- Телефонные номера, ссылки и Telegram-username в описании (см. §7.2).
- Дубликаты: одинаковый текст и фото у публикаций разных владельцев — на ручную проверку.
- Лимиты: не больше 5 активных публикаций в каждом разделе для обычного пользователя, 30 — для работодателя с подтверждённой компанией.

Результат проверки: пропуск, пометка «на проверку», блокировка публикации с сообщением.

### 8.2. Ручная модерация
- Очередь сортируется по времени поступления, жалобы и пометки подняты наверх.
- Срок реакции: 24 часа на обычные публикации, 4 часа на жалобы.
- Действия: одобрить, отклонить (обязательна причина из списка), запросить исправление (с комментарием), скрыть, заблокировать пользователя.
- Каждое действие пишется в журнал модерации.

### 8.3. Правила для работодателей
- Работодатель проходит проверку компании: название, регистрационный номер или ссылка на официальный источник, контактное лицо.
- Запрещено: брать плату с соискателя за трудоустройство, просить предоплату или залог за работу, публиковать вакансии без реального рабочего места.
- Платформа не гарантирует право на работу: в каждой вакансии с визой (E-9, F-4 и др.) показывается предупреждение о необходимости проверить допустимость работы по визе.

### 8.4. Правила для жилья
- Запрещено брать предоплату до просмотра или подписания договора на платформе, требовать перевод на личный счёт без договора.
- Платформа не проверяет право собственности. Предупреждение показывается при каждой публикации.

### 8.5. Правила для знакомств
- Запрещены: несовершеннолетние, коммерческий секс, поиск через платформу денег, фото других людей без согласия, оскорбления.
- Нарушение — блокировка анкеты и предупреждение, повторное нарушение — блокировка аккаунта.

### 8.6. Правила для барахолки
- Запрещены: оружие, наркотики, поддельные документы, краденые вещи, медицинские препараты без рецепта.
- Товары с ограничениями (авто, электроника с серийным номером) — только с фото документов по запросу модератора.

## 9. Монетизация (ТЗ № 2, интеграция)

Этот раздел заменяет §25 ТЗ v1.0 для MVP. Полные требования — в `docs/tz-2-monetization.md`.

Что добавляется к тексту ТЗ № 2:
- **Сущность «платное размещение»** (`paid_placements`): публикация, тип услуги (`bump`, `vip`, `pin`, `highlight`), дата начала, дата окончания, статус (`active`, `ended`, `refunded`). Выдача сортирует публикации с активным размещением по его приоритету.
- **Поднять** не меняет статус публикации и не отправляет её на модерацию. Ограничение: одна операция «поднять» на публикацию в 24 часа; кнопка неактивна до истечения. «Поднять» ставит публикацию первой в своей категории на 24 часа при сортировке по дате.
- **Закрепление и VIP** — отдельные размещения со сроком 7 дней, стакуются не более одного активного размещения каждого типа на публикацию.
- **Окончание размещения** — задача по расписанию каждые 5 минут. Снимает приоритет, уведомляет владельца, предлагает продление.
- **Возврат.** Полный возврат, если услуга не была оказана (ошибка активации, технический сбой, публикация отклонена модерацией в течение 24 часов после оплаты). Частичный возврат после активации не производится. Решение принимает администратор, возврат выполняется через `refundStarPayment`.
- **Выплаты владельцу.** Выручка в Stars накапливается на счёте платформы. Порядок вывода не определён, нужна проверка правил Telegram и юриста (см. §15, вопрос Q5). До решения вывод не реализуется.

## 13. Аналитика

Событие — одна строка в таблице `analytics_events` с полями: user_id (хэш), event, properties (без персональных данных), created_at.

| Событие | Когда |
|---|---|
| `app_open` | Открыта Mini App |
| `onboarding_step` | Шаг онбординга пройден |
| `search` | Поиск выполнен (запрос, без текста) |
| `listing_view` | Карточка открыта |
| `listing_create_start` / `listing_create_submit` | Начало и отправка формы |
| `listing_approved` / `listing_rejected` | Решение модератора |
| `message_sent` | Сообщение отправлено (без текста) |
| `favorite_added` | Добавлено в избранное |
| `payment_started` / `payment_success` / `payment_failed` | Оплата Stars |
| `refund_issued` | Возврат выполнен |
| `placement_expired` | Размещение закончилось |

Метрики: DAU, WAU, MAU; конверсия регистрации (открыли → прошли онбординг); конверсия публикации (начали создавать → отправили → одобрено); время модерации (медиана и 90-й перцентиль); конверсия в платную услугу (платящие / активные); количество обращений «Написать» и «Позвонить» на публикацию.

Целевые значения для MVP задаёт Product Owner. Без них метрики не используются для решений.

## 16. Тестирование и приёмка

### 16.1. Критерии приёмки по модулям

| Модуль | Критерий |
|---|---|
| Бот и вход | `/start` открывает Mini App; `initData` с неверной подписью отклоняется; язык определяется по Telegram |
| Онбординг | Нельзя продолжить без принятия соглашения; город сохраняется в профиле |
| Работа | Вакансия создаётся, уходит на модерацию, после одобрения видна в списке с фильтрами; «Написать» открывает диалог |
| Жильё | То же для объявления; точный адрес не виден в карточке |
| Барахолка | То же для товара; «Поднять» доступно раз в 24 часа |
| Знакомства | Пользователь младше 18 не может создать анкету; анкета без одобрения фото не видна другим; взаимный лайк открывает чат |
| Сообщество | Список групп и переход в Telegram-группу работают |
| Информация | Статья с устаревшей датой проверки показывает предупреждение |
| Профиль | Статусы публикаций отображаются верно; можно удалить аккаунт и выгрузить данные |
| Избранное | Добавление и удаление не влияют на объект; удалённый объект помечен |
| Чат | Сообщения доставляются; блокировка собеседника скрывает диалог от него |
| Уведомления | Каждый тип из §6.11 приходит в бот; отключённый тип не приходит |
| Модерация | Решение сохраняется в журнале; причина обязательна при отклонении |
| Платежи (ТЗ № 2) | Все критерии из §11 ТЗ № 2 |
| Админка | Роли ограничивают доступ; изменение цены не требует релиза |
| Безопасность | Нет доступа к чужим публикациям и чатам по прямой ссылке; загрузка файлов только разрешённых типов |
| Адаптивность | Экраны без горизонтальной прокрутки на iPhone SE, iPhone 15 и типичном Android |

### 16.2. Тестовые сценарии
- Регистрация и онбординг: новый пользователь проходит путь от `/start` до главной.
- Публикация и модерация: создать вакансию, отклонить с причиной, исправить, одобрить.
- Чат: два тестовых аккаунта обмениваются сообщениями, один блокирует другого.
- Оплата: тестовые Stars, оплата, активация, окончание, возврат.
- Выход на устройствах: iPhone и Android, светлая и тёмная тема Telegram.

### 16.3. Бета-тест
- Не менее 20 тестовых пользователей, 2 недели.
- Сбор обратной связи через бота (`/feedback`).
- Выпуск на продакшн только после закрытия критических и высоких дефектов.
