# KOREA HUB — ТЗ № 2: монетизация через Telegram Stars

Версия: 2.0
Назначение: дополнение и замена раздела 15 основного ТЗ.

## 1. Главное требование

Все платные цифровые услуги внутри Telegram оплачиваются только через Telegram Stars (⭐).
Валюта в Bot API: `XTR`.

Запрещено использовать внутри приложения:
- банковские карты и банковские переводы;
- USDT и другие криптовалюты;
- внешние платёжные шлюзы;
- любые другие способы оплаты цифровых услуг.

## 2. Принцип работы платежей

1. Пользователь выбирает платную услугу.
2. Система показывает стоимость в Stars.
3. Пользователь нажимает «Оплатить».
4. Бот формирует официальный Telegram Invoice.
5. Telegram открывает окно оплаты.
6. Пользователь подтверждает покупку.
7. Сервер получает подтверждение успешной оплаты.
8. Система автоматически активирует услугу.
9. Пользователь получает уведомление.

Услуга не активируется только по нажатию кнопки или ответу Mini App. Подтверждение платежа проверяется на сервере.

## 4. Пополнение и оплата

- Основной механизм: покупка каждой услуги напрямую через Stars.
- Обычный денежный кошелёк, внутренний баланс и обещание конвертации Stars в деньги не создаются.
- Пакеты и внутренний баланс — только отдельным решением после проверки на соответствие правилам Telegram.

## 5. Страница «Платные услуги» (Mini App)

Для каждой услуги: название, описание, стоимость в ⭐, срок действия, преимущества, кнопка «Оплатить N ⭐».

## 6. История платежей

Поля: дата и время, название услуги, количество Stars, статус, Telegram charge ID, связанное объявление.

Статусы: ожидает оплаты, оплачено, возврат выполнен, ошибка.

## 7. Административная панель — раздел «Монетизация»

Администратор может:
- менять стоимость услуг и создавать тарифы;
- отключать платные услуги;
- настраивать сроки VIP;
- просматривать все транзакции, количество покупок, выручку в Stars, возвраты;
- проверять спорные операции;
- смотреть графики: продажи за день, неделю, месяц; популярные услуги; количество платящих пользователей.

## 8. Техническая реализация

Методы Telegram Bot API:
- `createInvoiceLink` / `sendInvoice` с `currency=XTR`;
- `answerPreCheckoutQuery`;
- обработка `successful_payment`;
- `refundStarPayment` для возвратов.

Схема для Mini App: сервер создаёт ссылку на счёт через `createInvoiceLink`, Mini App открывает её через `Telegram.WebApp.openInvoice(url)`. `sendInvoice` сам по себе отправляет счёт в чат и из Mini App напрямую не вызывается.

Требования к серверу:
- проверять каждую транзакцию;
- сохранять `telegram_payment_charge_id`;
- обеспечивать идемпотентность: уникальный индекс на charge ID, активация в одной транзакции;
- не допускать повторной активации одной покупки;
- хранить историю операций;
- обрабатывать ошибки;
- обрабатывать возвраты и уведомления о них;
- не хранить и не запрашивать платёжные данные пользователя;
- соблюдать правила Telegram Stars для цифровых товаров и услуг.

Отдельно предусмотреть:
- `answerPreCheckoutQuery` вызывается быстро (Telegram ограничивает время ответа), проверка тарифа и цены — именно на этом шаге;
- если оплата прошла, а активация не удалась: повторная попытка активации, фоновая сверка платежей и автоматический `refundStarPayment`, если услугу выдать не удалось;
- срок жизни счёта и статус «ожидает оплаты» для просроченных счетов.

## 9. Автоматическое окончание VIP

- Система отслеживает дату окончания каждой услуги.
- По окончании снимает VIP-статус и возвращает объявление в обычную выдачу.
- Уведомляет пользователя и предлагает повторную покупку.
- Автоматическое списание Stars без нового подтверждения пользователя не выполняется.

## 10. Защита от мошенничества

- Уникальность платежей.
- Защита серверных уведомлений.
- Проверка принадлежности платежа пользователю.
- Не доверять данным об оплате из интерфейса.
- Не активировать услуги при ошибке подтверждения.
- Журнал действий администраторов.
- Защита API от повторных запросов.

## 11. Критерии приёмки

- Пользователь выбирает платную услугу.
- Оплата открывается официальным интерфейсом Telegram в Stars.
- Сервер получает подтверждение и активирует услугу автоматически.
- История платежей сохраняется.
- Администратор меняет тарифы без изменения кода.
- VIP автоматически заканчивается.
- Возвраты обрабатываются корректно.
- Повторное использование одного платежа не приводит к повторной активации.

## 12. Итоговое требование

Монетизация Stars интегрируется во все разделы (работа, жильё, барахолка, знакомства и далее) через единую систему тарифов и платежей. Архитектура расширяема: новые платные функции добавляются без переделки финансовой системы.

Принцип: пользователь выбирает услугу, оплачивает её Stars, система автоматически предоставляет оплаченные возможности.

Документ заменяет старый раздел монетизации и не создаёт вторую независимую платёжную систему.
